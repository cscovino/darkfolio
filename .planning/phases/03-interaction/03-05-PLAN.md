<objective>
Close UAT gap **G-03-6** — "browser has scrollbar and scroll a litle bit." `.page` is content-box sized with `min-height: 100dvh` plus `padding: 16px`, so its border box is always 32px taller than the viewport and the document keeps a scrollbar and scrolls exactly that 32px; the overlay's arrow keys scroll that document because focus lands on the non-scrollable `#game-overlay` panel while `.content` is the real scroller. And focusing `.content` alone would still not fix the keys: `createCursorKeys()`/`addKeys()` capture the cursor and WASD codes (`enableCapture` defaults to true), and Phaser's `KeyboardManager` listens on `window` in the bubble phase and calls `preventDefault()` for every captured code — so `ArrowDown` reaches the game and the browser's native scroll of the focused list is cancelled before it can happen.

Purpose: make the page chrome immovable so "each host opens its matching page; skills scroll internally; chrome never moves" is literally true.
Output: a viewport-height document with no page scrollbar, and an overlay whose content list owns keyboard scrolling while E/Esc keep closing it.

Design notes (binding choices made here, from the diagnosis in `.planning/debug/overlay-page-scrollbar.md`):
- **Root fix, not clipping.** `box-sizing: border-box` on `.page` makes `100dvh` the border box, so the document equals the viewport; it also makes `GameCanvas.astro`'s existing 40px budget (`calc(100vw - 40px)`, `calc((100dvh - 40px) * 4 / 3)`) coherent, since that formula already assumed the page padding sits inside the viewport. `html`/`body` stay as they are (`margin: 0`, no overflow lock).
- **Focus the scroller — and stop the event before the game sees it.** Two halves, both required. `.content` gets `tabindex="0"` and becomes the focus target (a focused `overflow-y: auto` element is natively keyboard-scrollable). Then the existing `document` keydown listener — already upstream of Phaser's `window` listener in the bubble path, and already the gate that keeps E/Esc out of the game's key capture — calls `stopPropagation()` for the eight contract scroll keys (`ArrowUp/Down/Left/Right`, `PageUp/Down`, `Home`, `End`). Phaser's handler never runs, so no `preventDefault()` is issued and the browser's default scroll of the focused `.content` proceeds. The guard must not call `event.preventDefault()` itself: cancelling the default is precisely what removes the scroll.
- **Why not drop the captures in the scene.** `removeCapture([...])` or toggling `keyboard.preventDefault` around the overlay would also work, but it puts the open/close lifecycle into `LivingRoomScene`, must be restored on close *and* on the scene's shutdown sweep, and loosens capture for the whole page in between. The panel's listener already owns key policy while the panel is open, so the guard belongs there — no new state, and the E/Esc branch is untouched.
- **The guard sits before the `ready`/`repeat` gate.** Scroll keys can never close the panel, so they carry none of the double-tap re-open race that `ready` defends against; and a held arrow must keep scrolling, so `event.repeat` must not swallow it. The E/Esc branch keeps its `event.repeat || !ready` gate and its `stopPropagation()` + `closePanel()` exactly as they are.
- **The panel keeps its own role.** `#game-overlay` stays `tabindex="-1"` per the UI-SPEC Focus row; it simply stops being the focus target, and that row is reconciled in Task 2.
- **`outline: none` on `.content`** follows the same UI-SPEC rationale the panel already uses: the CRT frame is the focus affordance, not a browser ring.
</objective>
