# Phase 3 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Surfaces in scope:** (1) the floating interaction prompt badge (world-anchored, Phaser); (2) the typewriter dialog box (screen-anchored, Phaser); (3) the CRT overlay panel (DOM over the canvas) showing the `/projects` · `/skills` · `/contact` pages; (4) the three placeholder Astro routes, which render standalone **and** inside the overlay.
> **Not in scope:** lighting/FX behind the overlay (Phase 4), audio cues (Phase 5), real portfolio content (Phase 6), sprites/tilemaps (Phase 7), title/loading/mobile screens (Phase 8).
>
> **Stack:** Astro 7.3.5 + Phaser 4.2.1 + TypeScript ^5. No Tailwind, no React, no shadcn, no component library, no icon library, no new dependency (AGENTS.md tech-stack lock, DEPL-02 no-CDN). Plain Astro scoped CSS + Phaser graphics/text.

## Canvas Framing & Layering

The game frame is **640 × 480 logical px**. The world camera is zoomed **4×** (Phase 1); every UI surface below is declared in **logical canvas px** and rendered at **zoom 1** — a second transparent UI camera (or an equivalent unzoomed layer). A world-space badge at zoom 4 would render 4× too large; this is the same rule the Phase 1 UI-SPEC set for the gate scene.

| Property | Value | Source |
|----------|-------|--------|
| Logical frame | 640 × 480 | `src/game/main.ts` |
| World camera | zoom 4, lerp 0.05 follow | Phase 1 |
| UI layer | zoom 1, transparent, always on top of the world | Phase 1 UI-SPEC ("Gate text rendering") |
| Page DOM | `#game-frame` is `position: relative`; the overlay is absolutely positioned inside it, clipped by `overflow: hidden` | this phase |
| Frame aspect | `#game-frame` is **always 4:3** (`width: min(640px, calc(100vw - 40px), calc((100dvh - 40px) * 4 / 3)); aspect-ratio: 4 / 3; height: auto;`) so the DOM overlay aligns pixel-exactly with the Phaser canvas at every viewport size | this phase (alignment requirement) |
| Overlay sizing | `width: 100%; height: 43.333%` **of the frame** (208 / 480) — never fixed px, so the panel tracks the canvas at any frame size | this phase |
| Overlay type scaling | overlay font sizes are declared in `cqw` against `#game-frame` (`container-type: size`): 12px → 1.875cqw, 16px → 2.5cqw, 20px → 3.125cqw (values are correct at the 640px reference width) so DOM text scales with the canvas instead of drifting | this phase |
| Reduced motion | `@media (prefers-reduced-motion: reduce)` collapses the DOM overlay slide to 0ms (panel appears instantly). Canvas slides and the typewriter are unaffected — the game is the content. | this phase |

**Layer order (bottom → top):** Phaser world → Phaser dialog box → Phaser prompt badge → DOM CRT overlay panel → DOM page chrome (standalone only).

## Interaction Contract

### Reach (deviation from D-23 — deliberate, with cause)

D-23 locks "radial, ~2 tiles (32 px) from object center". The Phase 2 Office layout makes that literal reading **unreachable**: the chair sits directly in front of the desk and the computer's rect centre is on the desk against the north wall, so the closest the player can physically stand is **46px** away. The Living Room TV has a couch + coffee table beneath it, putting its closest standing spot at exactly **32px**. A literal 32px centre radius therefore fails INTR-03 (Computer) and leaves the TV borderline.

**Locked resolution (user-confirmed): reach is measured as a rect gap, not a centre radius.**

> The player is **in range** of an interactable when the **gap between the player's 32 × 32 body rect and the object's rect is ≤ 32px**, the object is in the player's **current room** (D-23's same-room check via `roomAt(ROOM_ZONES, …)`), and no other interactable is nearer.

- Equivalent formulation for implementation: the player's body rect expanded by 32px on all sides intersects the object's rect.
- At the desk the gap is ≈15px, at the TV ≈16px — comfortable, and the 2-tile intent of D-23 is preserved.
- No line-of-sight / solid test (D-23): the desk between the player and the computer must **not** block the interaction.
- **Nearest wins** (D-24): compare gap values; the smallest gap wins. Ties break by **registry order** (first declared wins) so selection is deterministic.

### State machine

| State | Entered when | Badge | Dialog box | Overlay | Movement | `E` | `Esc` | Door triggers |
|-------|--------------|-------|------------|---------|----------|-----|-------|--------------|
| `idle` | default | hidden | hidden | closed | allowed | — | — | allowed |
| `prompt` | an object is in reach | **visible** on the nearest in range | hidden | closed | allowed | **start interaction** | ignored | allowed |
| `typing` | `E` in `prompt` | hidden (D-10) | visible, sliding in, typewriter running | closed | **locked** (D-27) | **skip to full text** (D-02) | **cancel dialog → slide out to `idle`** (D-02, amended 2026-10-26) | blocked (D-27) |
| `paused` | typing finished, **dialog-only** object | hidden | visible, `▼` cue blinking | closed | locked | ignored (D-29) | ignored | blocked |
| `handoff` | typing finished, **host** object → 1500ms read-hold → dialog slides out → overlay slides in | hidden | sliding out | sliding in | locked | ignored (D-29) | ignored | blocked |
| `overlay` | the overlay slide-in finished | hidden | hidden | visible | locked (D-28) | **close** (200ms slide down) | **close** | blocked (D-28) |
| `glide` | a door crossing starts | hidden | hidden | closed | locked (Phase 2) | ignored (D-29) | ignored | n/a |

- **The scene keeps rendering behind the overlay** (D-28) — the room strip above the panel stays live so Phase 4 lighting and Phase 5 ambient audio work for free.
- **Host flow (D-01):** `E` → typewriter → typing ends → 1500ms read-hold → dialog slides out (200ms) → overlay slides in (250ms) → `overlay`. The typewriter clock starts when the dialog box finishes sliding in, so the slide-in is outside the reveal window, and the handoff is **sequential, never overlapping**.
- **Dialog-only flow (D-04):** `E` → typewriter → typing ends → 1500ms pause with the blinking `▼` cue → dialog slides out (200ms) → `idle`.
- **`E`/`Esc` are ignored from the moment typing finishes until the overlay has finished sliding up** (D-29) — a double-tap cannot close the overlay it just opened.
- **`E` is ignored during a door glide** (D-29).
- **Movement is locked while the dialog is open** — velocity zeroed and door triggers blocked (D-27).
- The typewriter runs at **25ms per character** (≈40 chars/sec) and word-wraps at 44 chars/line; the reveal includes the wrap.

### Variant cycling (INTR-05)

- **One counter per object**, independent across objects (D-18) — the computer's third visit is not the phone's third visit.
- **Visit N (1-based) shows pool[(N − 1) % pool.length]**; the counter increments **atomically on the `E` press** that starts the interaction (D-19) — an interrupted or skipped interaction never double-counts or rolls back.
- **Dialog variant N and overlay status-line variant N are the same N** (D-18, synced).
- **The same flow runs on every visit** (D-21): dialog → auto-overlay, every time. There is no "seen" tracking separate from the counter.
- Pools hold **3 entries per object** (D-16 requires 3+), cycled A → B → C → A, deterministic, no randomness.
- State is **in-memory only** (D-20) — it resets on reload. Phase 5 owns `localStorage`.
