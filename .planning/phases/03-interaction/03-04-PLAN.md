<objective>
Close UAT gap **G-03-3** — "this slides up too soon, I could not read entirely the text before the dialog slides up." The host handoff currently begins on the exact frame the typewriter completes, so the completed line is at rest for a single render frame; and the reveal clock runs during the 250ms dialog slide-in, burning ~10 characters before the box lands. Fix both at their source and reconcile the UI-SPEC choreography that encoded the too-fast behaviour.

Purpose: restore the read beat the phase promised (dialog → *read it* → overlay) without touching the state machine's shape, the dialog-only flow, or the input locks.
Output: host handoff holds `READ_HOLD_MS` with the full line settled, the reveal window no longer overlaps the slide-in, and the spec's host-flow text matches the code.

Design notes (binding choices made here, from the diagnosis in `.planning/debug/dialog-auto-handoff-too-soon.md`):
- **`READ_HOLD_MS = 1500` in `src/game/systems/dialog.ts`** — mirrors `AUTO_DISMISS_MS` so both flows give the same settled beat. Length-scaling was considered and rejected: it adds a second timing rule for no observable gain once the reveal itself paces reading, and the gap's missing item names "mirroring AUTO_DISMISS_MS" first.
- **The hold lives inside `'handoff'`** — no new mode, no new timer class, no new key branch. The mode is already excluded from `handleInput`, the door check and E/Esc reads, so the hold is locked-down for free.
- **A skip still gets the hold.** D-02 says a skip jumps to full text and then "the normal flow continues"; the dialog-only path already waits its full 1500ms after a skip, so the host path matches that precedent rather than inventing a skip-aware exception.
- **No end cue on the host hold.** The ▼ cue is reserved for the auto-dismiss pause (UI-SPEC §Dialog box, End cue row); the host hold ends with motion (dialog out, panel up), which is its own signal.
- **The deferred start is shared, and that is the intended scope.** `startInteraction()` serves both flows, so TV/lamp also stop burning ~10 characters during the 250ms slide-in. That is a correction of a defect the dialog-only path had too — the rise was never readable time — and it changes nothing about the paused beat itself (`AUTO_DISMISS_MS`, the ▼ blink, `dismissPaused()`). No overlay-only conditional is added: branching here would preserve the unreachable-text burn for two of the five hosts to keep a phrase like "byte-for-byte unchanged" true.
- **The one `.planning/` edit is surfaced for approval (AGENTS.md §Never).** G-03-3's diagnosis records the UI-SPEC host-flow text as part of the defect, so the plan carries the exact wording, but Task 2 presents the two row edits to the user first and records the approval — or the refusal, with the resulting spec/code divergence as an open item — in `03-04-SUMMARY.md` instead of writing the file silently.
