## Design decisions documented by the planner (discretion per 04-CONTEXT "the agent's Discretion")

- **Static pools bake once, then stamp.** A per-light `pool-<lightId>` DynamicTexture (2*radius square) is built in the constructor: base ring texture stamped at (radius, radius), the world's wall-shadow quads (translated to DT-local space) accumulated into one Graphics and removed with a SINGLE erase plus a single `render()` flush. Per-quad erase under one trailing flush is wrong: Phaser's DT command buffer resolves the Graphics reference at flush and would replay only the last quad, so every other wall's shadow would vanish. Each frame the veil simply stamps that texture with ERASE (render-textures skill: ERASE removes darkness proportional to source alpha; command buffer needs the flush from Plan 01's veil.render()). This keeps per-frame cost flat as sources grow (D-21).
- **Tint = a second consumer of the same texture.** One `Phaser.GameObjects.Image` per light at depth 19, `setTint(light.color)`, `setAlpha(TINT_ALPHA)`, `setBlendMode(Phaser.BlendModes.ADD)` — additive coloured light under the veil, with the baked ring falloff providing the spatial step (D-11). The torch gets the same treatment in this plan's Task 1 via an image whose texture is the live `__TORCH__` DynamicTexture (render-textures skill: updates to a DynamicTexture reflect on all its users), so the warm tint inherits the torch's occlusion and lobe for free; its alpha is TORCH_TINT_ALPHA.
- **Flicker is a pure, stateless, O(1) function.** `brightnessAt(seed, elapsedMs, kind)` partitions time into blocks (`FLICKER_BLOCK_MS` = 1000 lamp / 2000 screen), picks a change offset of half or the full block from a hash bit, and picks the brightness value from a second hash of (block, sub-step). Consecutive changes therefore stay 500–1500ms apart for lamps (inside D-14's 0.5–1.5s band) and 1000–3000ms for screens (D-15's gentler cadence), with zero iteration cost and no state to reset on scene restart.
- **Fade state lives in LightLayer, keyed to the wall line, not to room arrival.** `beginFade(to, axis, dir)` is called by the scene at glide start; LightLayer detects `crossedAxis` from the per-frame player position (lighting update runs above the gliding early-return) and lerps the per-region alphas for FADE_MS. The fade holds its final values until `getCurrentRoom()` matches the destination, so the glide-end state flip can never snap the veil back (D-05 explicitly rejects the delayed flip).
- **Radii/colours stay in `lights.ts`** as Plan 01 wrote them (LAMP_RADIUS 88, SCREEN_RADIUS 40, TINT_ALPHA 0.2, TORCH_TINT_ALPHA 0.14) — no new tuning constants outside that registry and the flicker module's two bands.
