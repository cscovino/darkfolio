## Design decisions documented by the planner (discretion per 04-CONTEXT "the agent's Discretion")

- **Render technique = RenderTexture veil + shadow-erased pool textures. Phaser's native Lighting component / LightsManager is REJECTED** (verified against the vendored Phaser 4.2.1 skills `.opencode/skills/v4-new-features/SKILL.md` §Lighting and `.opencode/skills/render-textures/SKILL.md`): native lights cannot do geometric wall occlusion (D-03), only smooth falloff (D-06 needs quantized 2-step rims), only circular pools (D-08 facing-weighting), and one global ambient (D-01 needs per-room veil levels keyed to currentRoom). The veil approach: one world-sized (640×480) RenderTexture at depth 20, refilled every frame — black region fills at per-room alphas, then each light erases a hole via a stamp with the ERASE blend mode whose alpha is the light's brightness (erase removes darkness proportionally to source alpha — flicker later modulates alpha only, never radius, D-14). Occlusion: silhouette quads (pure `wallShadows` math) are erased out of each pool's own DynamicTexture before it ever touches the veil; doorway gaps are real gaps between wall rects, so D-02's "pool glimpsable through the 48px gap" falls out with zero special-casing. All draw ops buffer into the command queue and need the flush call every frame (render-textures skill gotcha #1); zero snapshot/readPixels usage (gotcha #7, D-21).
- **Two-step falloff recipe (D-06):** the base pool texture is three concentric white circles drawn outer→inner with per-circle alphas 0.25 / 0.34 / 1.0 at radius fractions 1.0 / 0.78 / 0.5 — source-over composition lands the removal levels at ≈ {0.25, 0.5, 1.0}: full-bright core (also discharges D-12 for the torch-covered player and, in Plan 02, the bulbs/screens), half-step mid ring, quarter-step rim.
- **Scene field is named `lighting`, NEVER `lights`** — Phaser.Scene already carries a built-in `lights` member (LightsPlugin, see `.opencode/skills/scenes/SKILL.md` line 106); shadowing it is a silent-collision class bug.
- **Veil constants live in `lighting.ts`** (VEIL_ALPHA, NEAR_BLACK_ALPHA; later FADE_MS) following the dialog.ts-owns-its-timing-constants precedent; light-source constants and the registry live in `lights.ts` following the rooms.ts data-registry precedent.
- **Pure layer takes arguments, not state imports** (proximity.ts precedent): `wallRects(layout, origin)`, `veilAlphaFor(current, region)`; the Phaser-side `LightLayer` owns the rooms.ts composition (`WORLD_WALLS`) and reads `getCurrentRoom()` at the scene boundary.
- **Radii (discretion inside D-10's locked hierarchy):** lamps 88px (5.5 tiles, band 5–6), screens 40px (2.5 tiles, band 2–3), torch 64px (4 tiles — locked by SC#2, expressed as 4*TILE). Veil alphas: 0.7 current (spec-literal 30% brightness) / 0.95 elsewhere ("near-black"). Tint alphas: 0.2 pools / 0.14 torch — both tint classes are rendered by 04-02; 04-01's torch stays a neutral veil erase. Torch lobe: offset 32px, scale 0.7, alpha 0.5 → facing reach ≈ 77px vs 64px behind (D-08 "slightly brighter / reaching further").
