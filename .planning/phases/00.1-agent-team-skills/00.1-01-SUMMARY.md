## Model Routing Evidence (the tracer's core finding)

1. First successful dispatch (no `--model`): exit 0, non-empty, keyword match — but the message record shows `model: {id: nemotron-3.5-super-vl-free, providerID: opencode}` — the **session default free model**, not the agent's declared `opencode-go/qwen3.8-flash`. No errors logged; cost 0. Kept as `.verify/smoke-scribe-run-default-model.log`.
2. Zero-cost diagnosis via the server API (`opencode api agent.get`): the parsed agent definition **does** carry `model: {id: qwen3.8-flash, providerID: opencode-go}`, `steps: 25`, and all five permission keys — the file format is correct; `opencode run` (2.0.29) simply does not apply the agent's frontmatter model when creating the session.
3. Second dispatch with explicit `--model opencode-go/qwen3.8-flash`: exit 0, non-empty, on-brief answer; message record `model: {id: qwen3.8-flash, providerID: opencode-go, variant: default}` — **real opencode-go/qwen3.8-flash routed call proven**. Canonical tracer log: `.verify/smoke-scribe-tracer.log`.

**Consequence for 00.1-04:** `scripts/smoke-team.sh` must pass `--model <D-03 id>` explicitly per agent — without it every smoke "pass" would silently run on the free default and prove nothing about routing. In-session task spawns (how the GSD orchestrator actually dispatches) resolve the agent definition server-side, where the parsed model lives.
