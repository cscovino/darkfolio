## Summary

Reviewed the harness/config phase: smoke harness, agent definitions, .gitignore unwind, and AGENTS.md roster. One invalid-YAML frontmatter (game-lead) is a blocker because OpenCode will fail to load that agent. One maintainability issue in the smoke harness and one advisory on argument validation.

## Critical Issues

### CR-01: Invalid YAML frontmatter in game-lead agent

**File:** `.opencode/agents/game-lead.md:3`
**Issue:** The `description` value contains an unquoted `: ` (colon-space) which breaks YAML parsing: "Planning and delegation lead: scopes phases, reviews artifacts, ...". PyYAML rejects it; OpenCode frontmatter parsing may likewise fail to load the game-lead subagent.
**Fix:**
```yaml
description: "Planning and delegation lead: scopes phases, reviews artifacts, routes work — Spawned by the GSD orchestrator."
```

## Warnings

### WR-01: Smoke harness uses subset lookup that can hide typos

**File:** `scripts/smoke-team.sh:23-25`
**Issue:** When invoked with unknown agent names, the loop silently skips them and still prints `SMOKE_TEAM_OK`, masking a misnamed selection. Also no validation that at least one agent ran.
**Fix:** Validate each requested name against the AGENTS list and exit non-zero if any unknown or if none matched.

## Info

### IN-01: Smoke harness relies on cwd for output location

**File:** `scripts/smoke-team.sh:9`
**Issue:** `.verify` is created relative to the current working directory. Running `pnpm smoke:team` from outside the repo root (or a worktree) writes logs where callers do not expect them. Minor; the package script assumes repo root.
**Fix:** Resolve the repo root (e.g. `cd "$(git rev-parse --show-toplevel)"`) before creating `.verify`.
