## Pattern Assignments

### `.opencode/agents/team/*.md` (7 agent definitions)

**Analog:** `.opencode/agents/gsd-planner.md` (lines 1–9) and `.opencode/agents/gsd-executor.md` (lines 1–8) — 64 working agent files in `.opencode/agents/` prove this exact shape is discovered and dispatched by OpenCode.

**Frontmatter pattern** (gsd-planner.md lines 1–9, verbatim):
```yaml
---
name: gsd-planner
description: Creates executable phase plans with task breakdown, dependency analysis, and goal-backward verification. Spawned by /gsd-plan-phase orchestrator.
mode: subagent
permission:
  websearch: deny
  task: deny
  todowrite: deny
---
```

**Secondary confirmation** (gsd-executor.md lines 1–8) — same shape, adds `webfetch: deny`:
```yaml
---
name: gsd-executor
description: Executes GSD plans with atomic commits, deviation handling, checkpoint protocols, and state management. Spawned by execute-phase orchestrator or execute-plan command.
mode: subagent
permission:
  webfetch: deny
  websearch: deny
  task: deny
  todowrite: deny
---
```

**How to apply per team agent** (from CONTEXT.md D-03..D-08):
- `name:` = file basename (`game-lead`, `phaser-specialist`, …), `description:` = one line: role + who spawns it (mirror the gsd style "Spawned by …").
- `mode: subagent` — all 7 (D: phase boundary text).
- `model: opencode-go/<id>` — **new field, no in-repo precedent** (verified: `grep -rlE "^(model|steps):" .opencode/agents/` = zero hits). Exact IDs verbatim from D-03 table; never `claude-*`/`gpt-*`/`grok-4.7` (D-02).
- `steps: 25|60` — **new field, no in-repo precedent.** Tier per D-06: game-lead/designer/scribe/pixel-artist = 25; phaser-specialist/gameplay-dev/qa = 60.
- `permission:` map per-role:
  - `task: deny` on all 7 (D-07 — matches house style exactly; every gsd agent has it).
  - `edit: allow|deny` per D-04 (deny: qa, game-lead).
  - `bash`: allow-list strings for gameplay-dev/phaser-specialist/qa (`pnpm *`, `git *`, `node *` allowed; `rm -rf*`, `git push*` denied); `bash: deny` for the other 4 (D-05).
  - `websearch`/`webfetch`: `allow` only for phaser-specialist + designer; `deny` for the other 5 (D-08). Note gsd agents only ever show the `deny` direction — the `allow` value is the inverse of the excerpted pattern, same key shape.
- **Body:** gsd agents carry huge instruction bodies; team agents need only a short role paragraph ("copy the shape, trim the body" per CONTEXT §Reusable Assets). The markdown body after `---` is free-form instructions injected into the subagent's prompt.

**Discovery-path caveat (D: Discretion):** all 64 existing agents are **flat** in `.opencode/agents/`. `.opencode/agents/team/` nesting is unproven in this repo — executor must verify OpenCode discovers nested agents; fallback is flat files named `game-lead.md` etc. (Keep the intent: a clearly separated team.)

### `scripts/smoke-team.sh` (or `.mjs`) — dispatch smoke harness (D-12..D-14)

**Analog:** Phase 0's `.verify/` convention, `.planning/phases/00-setup-foundation/00-PLAN.md` `<automated>` chains (e.g. Task 1 line 260, Task 4 lines 369–372). Established shape:

```bash
mkdir -p .verify && <command> 2>&1 | tee .verify/<name>.log && test ${PIPESTATUS[0]} -eq 0 && grep -F "<sentinel>" .verify/<name>.log && echo OK
```

**How to apply:** per-agent loop over the 7 names, each iteration:

```bash
mkdir -p .verify
opencode run --agent "$agent" "$toy_task" > ".verify/smoke-$agent.log" 2>&1; rc=$?
test $rc -eq 0 && test -s ".verify/smoke-$agent.log" && grep -qiE "$keyword" ".verify/smoke-$agent.log"
```

- Pass bar per D-13 is exactly the three mechanical asserts above: exit 0 + non-empty output + per-agent keyword grep (game-lead → phase number; pixel-artist → hex color; toy-task wording and keywords are planner/executor's call). No LLM judge.
- Exit non-zero on first failure (fail-fast like the Phase 0 `&&` chains) but keep all logs in `.verify/` for the one-time human skim.
- Language: shell vs node is discretion; shell matches the existing `tee`/`${PIPESTATUS}` idiom and `.husky/pre-commit` (`bash`, hook files tracked at `.husky/`).
- `.verify/` is gitignored (`.gitignore` line 6) — logs stay out of commits; the script itself lives in tracked `scripts/` (new dir — no `scripts/` exists yet, no conflict).
- **Not wired into husky/CI** (D-14) — do not touch `.husky/*`.

### `.gitignore` *(modify)* — D-11 negation rules

**Analog:** the current file itself (12 lines, verbatim, line 5 is the edit target):
```gitignore
node_modules/
dist/
.astro/
.codegraph/
.opencode/
.verify/
coverage/
*.log
.DS_Store
.env
.env.local
.env.*.local
```

**Critical gotcha (git semantics, not a repo pattern):** line 5 `.opencode/` ignores the *directory*, and git "is not possible to re-include a file if a parent directory of that file is excluded." A naive `!.opencode/agents/team/*.md` appended after `.opencode/` matches nothing. The rule must be rewritten so git descends into `.opencode/`:

```gitignore
.opencode/*
!.opencode/agents/
!.opencode/skills/
.opencode/agents/*
!.opencode/agents/team/
.opencode/skills/*
!.opencode/skills/phaser*/
!.opencode/skills/v3-to-v4-migration/
!.opencode/skills/astro/
!.opencode/skills/pixel-art/
```

(Exact pattern shape is discretion per CONTEXT; the directory-path-unwind above is the only known-correct approach. Verify with `git check-ignore -v .opencode/agents/team/game-lead.md` and `git status` showing the 7 team files + new skill dirs as untracked-addable while `gsd-*` dirs stay ignored.)

**Verify command precedent** (from 00-PLAN Task 1 line 260): content-lock the edit with greps like `grep -F ".opencode/" .gitignore` replaced by the new shape, and `! git check-ignore .opencode/agents/team/game-lead.md`.

## Shared Patterns

**Apply to:** all team agents — describe the role then who dispatches it (the GSD orchestrator / game-lead), keeping D-07's `task: deny` honest: team agents are leaves.

**Source:** `.planning/phases/00-setup-foundation/00-PLAN.md` `<automated>` chains (lines 260, 314, 369–372)
**Apply to:** `scripts/smoke-team.*` and every 00.1 plan task's `<verify>` block — write logs under `.verify/` (gitignored), assert with `grep -F` sentinels, `test -s` for non-emptiness.

**Source:** all 64 `.opencode/agents/gsd-*.md` (e.g. gsd-executor.md lines 5–8)
**Apply to:** team agent `permission:` maps — enumerate explicit denies; only phaser-specialist/designer get web `allow`s (D-08), only 3 coders get `bash` allow-lists (D-05).

**Apply to:** every 00.1 commit — e.g. `✨ feat(config): add agent team roster to .opencode/agents/team/` — tasks touching AGENTS.md/.gitignore/package.json must pass the commit-msg hook. Scope candidates: `config` (agents/skills/gitignore), `hooks`/`build` (scripts), `docs` (AGENTS.md).
