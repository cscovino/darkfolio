# Phase 00.1: Agent Team & Skills - Context

**Gathered:** 2026-10-15
**Status:** Ready for planning

<domain>
## Phase Boundary

A 7-agent specialist team exists under `.opencode/agents/team/` (game-lead, phaser-specialist, gameplay-dev, qa, pixel-artist, designer, scribe), each declaring an explicit `model`, `mode: subagent`, `edit` permission guardrails, and a `steps` limit. Agent Skills are installed under `.opencode/skills/`: the 28 official Phaser 4 skills + `v3-to-v4-migration` (vendor-copied from Phaser's first-party skills), plus hand-authored minimal Astro and pixel-art skills. Every agent passes a dispatch smoke test proving model routing works, and AGENTS.md documents the roster and routing rules so later phases can run near-autonomously via `/gsd-autonomous`.

**Not in scope:** changing GSD plugin internals, adding project dependencies, any `src/` game code (that's Phases 1+), CI wiring.

</domain>

<decisions>
## Implementation Decisions

### Per-role model assignment
- **D-01:** 3-tier by role weight, cost model = price × call-volume: expensive models on rarely-invoked planning/design roles, cheap models on high-volume execution roles. — **Reversibility:** reversible — each model is one frontmatter line per agent file.
- **D-02:** Hard constraint: user's subscription is OpenCode Go only. **Never use `claude-*` or `gpt-*` model IDs.** `grok-4.7` is uncertain on the user's plan — avoid it too. Stick to qwen / kimi / deepseek / glm / mimo / minimax / step families from the opencode-go catalog.
- **D-03:** Locked model map (exact IDs as they appear in the opencode-go catalog):
  | Agent | Model | Rationale |
  |---|---|---|
  | game-lead | `opencode-go/qwen3.8-max` | Frontier reasoning for planning/architecture; called ~1×/phase |
  | phaser-specialist | `opencode-go/kimi-k2.7-code` | Code-specialist, long context for the 28 Phaser skills + migration guide |
  | gameplay-dev | `opencode-go/glm-5.3` | Strong agentic coder, mid price; highest call volume must be affordable |
  | qa | `opencode-go/deepseek-v4-pro` | Methodical review/analysis strength; medium volume |
  | designer | `opencode-go/kimi-k3` | Frontier all-rounder for design contracts; low volume |
  | pixel-artist | `opencode-go/mimo-v2.5-pro` | Multimodal — can actually look at sprite sheets/PNGs |
  | scribe | `opencode-go/qwen3.8-flash` | Docs/markdown is mechanical; cheapest |
- If the user later confirms grok/gemini access, designer/pixel-artist swaps are one-line edits.

### Permission guardrails per agent
- **D-04:** Edit stance = "builders allow, reviewers deny": `edit: allow` for phaser-specialist, gameplay-dev, pixel-artist, scribe, designer; `edit: deny` for qa (reports findings only; dev applies fixes) and game-lead (plans/delegates, never writes).
- **D-05:** Bash: allow-list for the three coders (gameplay-dev, phaser-specialist, qa) — `pnpm *`, `git *`, `node *` allowed; `rm -rf*` and `git push*` denied. `bash: deny` entirely for game-lead, designer, scribe, pixel-artist.
- **D-06:** Steps limits, role-tiered: game-lead / designer / scribe / pixel-artist = 25; phaser-specialist / gameplay-dev / qa = 60.
- **D-07:** `task: deny` for all 7 — the GSD orchestrator owns dispatch; no nested agent trees (mirrors existing gsd-* agents).
- **D-08:** Web access: `websearch`/`webfetch` allow **only** for phaser-specialist (Phaser 4 docs) and designer (visual references); deny for the other 5.

### Skill sourcing & install
- **D-09:** Phaser skills = official vendor-copy: the 28 first-party Phaser 4 skills + `skills/v3-to-v4-migration/SKILL.md` from the phaserjs/phaser repo (skills-hub.ai/sources/phaser), copied into `.opencode/skills/`. Pinned snapshot — no auto-update mechanism; re-copy manually when Phaser releases.
- **D-10:** Astro + pixel-art skills = hand-authored, ONE minimal SKILL.md each (~100 lines). Astro skill: Astro 7.3 static output, `base: '/darkfolio/'` path rules, pnpm 12 commands, content collections. Pixel-art skill: Darkwood palette hexes, 16×16 tiles / 32×32 character conventions, sprite-sheet + Aseprite rules — sourced from `.planning/PROJECT.md` §Context. No third-party/community skill code enters the repo.
- **D-11:** Version control: `.opencode/` stays gitignored EXCEPT new negation rules tracking `.opencode/agents/team/*.md` and the new skill dirs (`phaser*`, `v3-to-v4-migration`, `astro`, `pixel-art`). The 72 plugin-managed `gsd-*` skill dirs stay ignored (regenerated by gsd install). — **Reversibility:** costly — undoing re-hides the team from clones and re-editing .gitignore/AGENTS.md; requires reverting a published .gitignore convention. AGENTS.md's gitignore bullet gets a one-line amendment (user approved this by choosing the option).

### Smoke-test mechanism
- **D-12:** Committed harness script (e.g. `scripts/smoke-team.*`) that per agent runs `opencode run --agent <name> "<toy task>"`, captures output to `.verify/`, re-runnable with one command.
- **D-13:** Pass bar = cheap mechanical asserts: exit code 0 + non-empty output + per-agent keyword grep (e.g. game-lead mentions a phase number; pixel-artist emits a hex color). No LLM-judge scoring. A human skims the `.verify/` log once.
- **D-14:** Cadence: runs once as a plan task during Phase 00.1 execution; exposed as `pnpm smoke:team` for on-demand re-runs (after model/plan changes). **NOT** wired into pre-push or CI — real model calls behind every push burn the monthly quota.

### The agent's Discretion
- Toy-task wording per agent, harness language (shell vs node), exact keyword assertions, `.gitignore` negation pattern shape, and the roster section's placement inside AGENTS.md are the planner/executor's call.
- Whether the 7 agents live flat in `.opencode/agents/` vs `.opencode/agents/team/` follows ROADMAP SC#1 (`.opencode/agents/team/`) unless OpenCode's agent discovery turns out to require flat files — executor verifies discovery and adapts, keeping the intent (a clearly separated team).

</decisions>
