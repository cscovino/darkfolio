# Phase 1 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> Surfaces in scope: (1) Astro landing page `src/pages/index.astro` + `src/components/GameCanvas.astro` — framed centered canvas on a dark page (D-12/D-13); (2) in-game scenes — BootScene → "press any key" gate → LivingRoomScene with placeholder rect art in the Darkwood palette (D-08…D-11, D-14). All decisions pre-supplied by 01-CONTEXT.md; open gaps (cold-blue hex, player outline, gate flavor copy, canvas font) filled with prescribed defaults under the Discretion grant.

## Canvas Framing (layout contract)

Prescriptive defaults under the Agent's Discretion grant (01-CONTEXT.md); if the planner picks a different base resolution, all px in this spec scale proportionally.

| Property | Value | Source |
|----------|-------|--------|
| Logical canvas | 640×480 (obvious candidate named in Discretion) | default |
| World camera zoom | 4× → visible world ≈160×120 px (half-room) | D-05 |
| Scale mode | `Phaser.Scale.FIT` + `CENTER_BOTH`, integer zoom steps, `pixelArt: true`, `roundPixels: true` — identical composition on every screen, never RESIZE-reveals-world | D-13 |
| Page layout | Flex-centered canvas box, `min-height: 100dvh`, `overflow: hidden` (no scroll content), page background `#2A2A2A` | D-12 |
| Frame | 4px solid `#4A3729` CSS border on the canvas box — the "framed CRT on a dark wall" read. No scanline/shader effect this phase (deliberately skipped; CRT aesthetic is Phase 3+ polish) | D-12, defaults |
| Gate text rendering | Gate/prompt text is declared in logical canvas px — render through a UI camera at zoom 1 (or pre-scale by 1/zoom). The 4× world zoom would otherwise blow 32px into 128px. | default |

## Spacing Scale

Declared values (must be multiples of 4). In-game geometry is quantized to the 16px tile grid — stricter than this scale; every dimension below is tile- or pixel-snapped.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Canvas frame border, gate line-gap, minimum pixel-snap unit |
| sm | 8px | Gate copy block padding, facing-notch rect (8×8) |
| md | 16px | Tile unit — all walls/floor/furniture dims are 16px multiples; page gutter ≥16px around canvas box |
| lg | 24px | Unused this phase (scale member reserved) |
| xl | 32px | Player unit (32×32), minimum furniture footprint |
| 2xl | 48px | Unused this phase (scale member reserved) |
| 3xl | 64px | Unused this phase (scale member reserved) |

Exceptions: player outline is 2px (pixel-art hairline, sub-token — see Color). No touch-target exception: desktop-only phase; mobile blocking overlay is Phase 8.

## UI Considerations

Resolved by the post-verification UI-consideration probe (2026-10-19): 3 covered (explicit), 0 backstop, 0 unresolved. Unclassified rows E1 (page frame) and E4 (player sprite) reviewed manually — covered by the Canvas Framing and Color element-map contracts; no hidden state axis. No focused/hover state kinds: single canvas, keyboard-only input this phase.

**Truths (explicit, liftable):**
- The press-any-key gate scene is the only pre-play screen: PreloadScene is pass-through (zero assets), no progress bar renders, and the gate advances on first `keydown` with its one-shot listener removed on transition.
- Viewport overflow is contractually impossible: `Scale.FIT` + integer zoom + `CENTER_BOTH` keeps the visible world ≈160×120 px and the composition identical on every screen; the page is `overflow: hidden` (D-13).
- The populated happy-path state of the Living Room is the Color-section element map (D-01…D-11): 20×15 tile room, checkerboard floor, 4-tile walls, collision-only furniture set (TV, couch, lamp, coffee table), styled-only door gaps — hand-placed constants, no data-driven composition.

**Dismissed categories (reasons recorded — no silent drops):**
- long-text — all copy is fixed literals defined in the Copywriting Contract (`PRESS ANY KEY`, `the house is listening`, `Darkfolio`); no dynamic text ships this phase.
- error — zero fetching, zero assets; Phaser's WebGL→Canvas renderer fallback is automatic; AGENTS.md forbids error handling for impossible scenarios. SC#5 is a verification criterion, not UI copy.
- empty / partial / zero-one-many — the room is hand-placed, static, and always fully populated (D-01 fixes the furniture set).

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| loading | Boot → Preload → gate scene | ✅ covered (explicit) | Gate scene contract — see Truths |
| overflow | Canvas box on arbitrary viewports | ✅ covered (explicit) | FIT/integer-zoom contract — see Truths |
| populated | LivingRoomScene | ✅ covered (explicit) | Element-map contract — see Truths |
| long-text | Gate CTA, subline, page title | 🚫 dismissed | Fixed literal copy |
| error | All surfaces | 🚫 dismissed | Zero fetch/asset; automatic fallback |
